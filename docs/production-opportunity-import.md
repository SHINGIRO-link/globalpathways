# Production Opportunity Import Runbook

This runbook imports the validated catalogue from `backend/opportunities/uploaded_opportunities.json` into the Django production database. It uses `update_or_create` keyed by `slug`, so rerunning it is idempotent and does not delete unrelated opportunities.

## Recommended Render shell command

Open the Render service shell for the `globalpathways` service, confirm the checked-out commit is `d7b90a3`, and run:

```bash
cd /app/backend
python manage.py migrate --noinput
python manage.py import_uploaded_opportunities
```

Expected output:

```text
Imported 70 opportunities with update_or_create.
```

If the service uses a different working directory, run the same command from the directory containing `manage.py`:

```bash
pwd
find / -path '*/manage.py' -print 2>/dev/null | head
cd /app/backend
python manage.py import_uploaded_opportunities --file opportunities/uploaded_opportunities.json
```

## Django shell fallback

Use this if the management command is unavailable but the JSON file is present in the deployed container:

```bash
cd /app/backend
python manage.py shell <<'PY'
import json
from pathlib import Path
from django.utils.dateparse import parse_datetime
from opportunities.models import Opportunity

path = Path('opportunities/uploaded_opportunities.json')
rows = json.loads(path.read_text(encoding='utf-8'))
if len(rows) != 70:
    raise SystemExit(f'Expected 70 rows, found {len(rows)}')

for row in rows:
    values = dict(row)
    values['deadline'] = parse_datetime(values['deadline'])
    slug = values.pop('slug')
    Opportunity.objects.update_or_create(slug=slug, defaults=values)

print('Imported', Opportunity.objects.count(), 'opportunities total')
print('Imported rows with source URLs:', Opportunity.objects.filter(source_url__gt='').count())
PY
```

## API verification

Run:

```bash
curl -fsS https://globalopportunityconnect.com/api/opportunities/ > /tmp/opportunities.json
python - <<'PY'
import json
from pathlib import Path
rows = json.loads(Path('/tmp/opportunities.json').read_text())
assert isinstance(rows, list), type(rows)
assert len(rows) == 70, len(rows)
assert len({row['slug'] for row in rows}) == 70
assert all(row['source_url'] for row in rows)
required = {
    'id', 'title', 'slug', 'category', 'category_label', 'status',
    'status_label', 'country', 'region', 'deadline', 'deadline_note',
    'source_name', 'source_url', 'source_verified_at', 'summary',
    'description', 'eligibility', 'required_documents', 'featured',
}
assert required.issubset(rows[0]), sorted(set(rows[0]) - required)
print('API verification passed:', len(rows), 'opportunities')
print('First opportunity:', rows[0]['title'])
PY
```

The endpoint returns a JSON array. Each object contains the fields listed above; `category_label` and `status_label` are read-only display labels generated by Django.

## Important database note

The current Django settings use SQLite by default. A Render web service filesystem is not a durable production database unless a persistent disk is attached. For durable production data, configure a managed PostgreSQL or MySQL database and update `DATABASES` accordingly before relying on this import as permanent production data.
